# Sparnarok: The Architect's Codex - Agent Directives

## 1. Core Philosophy
You are an expert Full-Stack Developer agent working on "Sparnarok: The Architect's Codex".
Quality, testing, documentation, and mathematical precision are non-negotiable.

## 2. Tech Stack
- **Backend:** .NET 10 (C#), Entity Framework Core.
- **Database:** PostgreSQL.
- **Frontend:** React (TypeScript, Vite).
- **Localization:** i18n support from day zero (Frontend: react-i18next, Backend: .NET Localization).
- **Documentation:** Swagger/OpenAPI (Backend), TSDoc (Frontend), and ADRs (Architecture Decision Records) in markdown for system design.
- **Testing:** 
  - Backend Unit/Integration: xUnit + Moq/NSubstitute + Testcontainers.
  - Frontend: Vitest + React Testing Library.
  - E2E: Playwright.

## 3. The Definition of Done (Commit Protocol)
You CANNOT create a commit for a new feature unless ALL of the following conditions are met:
1. **100% E2E Testing:** The feature is fully covered by a Playwright E2E test simulating user behavior.
2. **Maximum Coverage:** Backend logic (especially the Combat Engine math) and Frontend components have comprehensive unit tests.
3. **Integration Verification:** Backend integration tests successfully write to and read from a real PostgreSQL instance.
4. **All Tests Pass:** The entire test suite executes locally without a single failure.
5. **i18n Compliance:** No hardcoded strings exist in the UI or API responses. All text is routed through localization dictionaries.
6. **Documentation Updated:** The feature is fully documented. This includes XML comments for C# public APIs, TSDoc for React components/hooks, Swagger annotations, and a new ADR in the `/docs/adrs` folder if a significant architectural or mathematical decision was made.

## 4. Git Workflow
- Prefix commits with semantic types (feat:, fix:, docs:, test:, chore:, refactor:).
- Never push straight to `main`. Every feature requires a branch and a pull request structure.
